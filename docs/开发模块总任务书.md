# 开发模块总任务书

## 协作规则

- `main` 始终保持可运行、可演示。
- A 负责后端、数据处理与部署；B 负责前端、三维交互与教学页面。
- 每个模块使用独立 feature 分支，通过 Pull Request 审查、联调后合入 `main`。
- 跨端模块由主负责人发起 PR，另一人审查。

## M0 工程底座

- 分支：`feature/m0-foundation`
- 范围：Vue 3、FastAPI、PostgreSQL、Redis 的最小可运行工程；JWT 登录、角色骨架、数据库迁移、统一异常与 OpenAPI。
- 验收：Docker Compose 可启动；管理员、教师、学生预置账号可登录；README 可让新设备完成启动。

## M1 案例导入与转换

- 分支：`feature/m1-case-import-convert`
- 负责人：A 主，B 配合。
- 范围：管理员创建案例、上传 LAS/LAZ、受控存储、PDAL 信息提取、Potree 转换、转换任务状态。
- 验收：原始文件不公开；状态可由 `DRAFT` 经 `PROCESSING` 变为 `READY`；可查看点数、范围、文件大小与失败原因。

## M2 三维浏览与标记

- 分支：`feature/m2-pointcloud-viewer`
- 负责人：B 主，A 提供接口。
- 范围：Potree 查看、旋转缩放漫游、点标记、重点区域、两点测距、相机状态保存。
- 验收：受控 Viewer 可加载 READY 案例；刷新后可恢复本人的标注、测距与相机状态。
- 标注必须含 `owner_id`、`scope`、`task_id`、`submission_id`，并按教师参考、学生草稿、提交快照、脱敏遮挡规则隔离。

## M3 学生实训

- 分支：`feature/m3-student-practice`
- 负责人：B 主，A 提供接口。
- 范围：任务列表、受限教学副本、标记与测距、勘验笔录、草稿和提交。
- 验收：学生只可访问本班有效任务；提交后生成不可被普通编辑覆盖的版本。

## M4 教师教学管理

- 分支：`feature/m4-teacher-management`
- 负责人：B 主，A 配合。
- 范围：课程、班级、任务、评分点、发布/关闭任务、查看提交、评分和反馈。
- 前置条件：先完成 M5a 的案例发布与有效期校验。
- 验收：教师只能管理本人课程；学生只能看到自己的任务、成绩和反馈。

## M5 案例版本与审计

- 分支：`feature/m5-version-audit`
- 负责人：A 主，B 配合。
- M5a：实现 `READY → PUBLISHED`、教学副本、有效期校验、任务绑定后版本不可覆盖。
- M5b：实现版本谱系、授权管理、审计查询和日志时间线。
- 验收：上传、发布、查看、提交、评分均产生审计记录；过期版本禁止新建任务和学生访问。

## M6 脱敏增强

- 分支：`feature/m6-desensitization`
- 负责人：A 主，B 配合。
- 范围：管理员绘制三维敏感区；`HIDE` 强制视觉遮挡；`DELETE` 使用 PDAL 生成物理删除的派生点云。
- 验收：派生版本可独立转换、加载、发布；教学端无法关闭脱敏遮挡规则。

## 合入顺序

`M0 → M1 → M2 → M5a` 后，`M3` 与 `M4` 可并行联调；之后完成 `M5b → M6`。

## Pull Request 最低要求

- 关联对应模块分支；
- 另一位开发者完成审查；
- 后端接口可在 Swagger 测试，前端主流程可操作；
- 数据库变更包含迁移文件；
- 环境变量变更同步更新 `.env.example`；
- 合并前完成构建、基础接口测试和本地演示流程。
